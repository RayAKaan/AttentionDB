## Caption drafts (§28)

- **Figure 1.** AttentionDB retrieval architecture: independent per-view HNSW
  heads produce candidate lists; a learned gate scores head usefulness from
  the query representation; normalized per-head scores are fused with
  optional exact rerank and candidate-level attention, followed by
  deterministic top-K.
- **Figure 2.** Frozen Phase 2 ablation (accepted baseline). Ground truth was
  later corrected (HC-4), so absolutes are not comparable with Phase 2B;
  mode ordering was stable across runs.
- **Figure 3.** Retrieval quality of fixed multi-head fusion, learned
  query-dependent gating, RRF, and oracle head selection across the
  controlled, noise, and multiview corpora. Values are measured on held-out
  test queries.
- **Figure 4.** Test R@10 versus training-set size on the multiview corpus:
  gating is at the uniform solution through 420 training queries and
  transitions by 840.
- **Figure 5.** Per-head diversity (mean pairwise Jaccard@10) versus utility
  (mean per-head Recall@10). Diverse heads can be near-useless; the axes are
  independent.
- **Figure 6.** Predicted gating weight versus actual head quality on held-out
  test queries (jittered to show point density); Pearson r annotated per
  corpus.
- **Figure 7.** Recall@10 versus p50 latency (log scale) for the frozen Phase
  2 pipeline modes, one shared VM — machine-specific, indicative ratios only.
- **Figure 8.** Fraction of test queries routed to each head by the learned
  gate, per query group (controlled corpus): routing matches the group
  structure without ever observing the label.
- **Figure 9.** Exact-score fusion under uniform, best-head, and oracle head
  weighting versus normalized uniform fusion. Head weighting — not score
  exactness — explains the Phase 2 exact-rerank regression.
- **Figure 10.** (PENDING) Effect of trained QK attention relative to gating
  alone; will be produced from PH2C-QK runs when they exist.
